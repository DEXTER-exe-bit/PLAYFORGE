# Security Policy

## Supported Versions

PLAYFORGE is currently in its initial public preview. Security fixes will primarily target the latest released version.

| Version | Supported |
| ------- | --------- |
| 0.1.x   | Best effort |

## Reporting a Vulnerability

Please **do not report security vulnerabilities through public GitHub issues**.

If private vulnerability reporting is enabled for this repository, use GitHub's **Report a vulnerability** feature under the repository's Security tab.

If private reporting is unavailable, contact the repository maintainer privately through GitHub to arrange a secure reporting method.

When reporting a vulnerability, please include:
- A clear description of the issue and its potential impact.
- The affected version and environment.
- Steps to reproduce the issue safely.
- Relevant logs or screenshots, with passwords, API keys, tokens, and other secrets removed.

## What to Expect

I will review reports as time permits and may ask for additional information to reproduce the issue. If the vulnerability is accepted, I will work toward an appropriate fix and release. If it is declined, I will explain the reasoning where practical.

Please allow time for investigation and remediation before publicly disclosing an unpatched vulnerability.

## Scope

This policy covers security vulnerabilities in PLAYFORGE's code, configuration handling, bot connections, and dependencies.

Only test systems you own or have explicit permission to test. Do not include real credentials or other people's private information in reports.
